# 上架类目与资质清单（企业知识助手 Connector）

> 本文用于 WorkBuddy 连接器上架时的「类目选择」与「主体资质」核对。
> 平台字段与分类白名单可能调整，**标「待核对」的条目以官方文档/后台为准**（见 `connector/README.md` 阻塞项）。

## 1. 连接器定位

- 名称：企业知识助手（`source: enterprise-knowledge-assistant`，kebab-case 全局唯一）。
- 一句话：面向企业内部的**只读知识问答 + 数据脱敏**助手，覆盖制度问答、员工/预算/合同查询、隐私脱敏与风险检查。
- 形态：远程 MCP Server（streamableHttp），**MCP 原生 OAuth（公共客户端 + PKCE）**，私有化部署。

## 2. 推荐类目

采用官方《专家》文档公布的 `categoryId` 枚举（15 个，官方《技能》文档未公布独立枚举）：

| 层级 | 取值 | 说明 |
|---|---|---|
| `SKILL.md` 的 `category` | **`04-DataAI`（数据智能）** | 官方说明涵盖「知识管理、AI 应用」，贴合本连接器 |
| 备选 | `11-SecurityCompliance`（法务安全） | 脱敏 / 敏感词 / 合规审查能力贴合 |
| 市场次标签（展示用） | 知识库 / 企业知识、数据安全 / 脱敏、组织与人事查询 | 非 frontmatter 字段 |

- 官方《技能》文档仅给出示例 `category: writing # 分类之一`，**未列出完整枚举**；当前取官方 `categoryId` 值 `04-DataAI`。
- **待核对**：提交前与运营确认「技能 category 白名单」是否与专家 `categoryId` 一致（见 `connector/README.md` 阻塞项）。

## 3. 工具与类目映射

对外开放 8 个只读工具（12 个中禁用 4 个，详见 `docs/合规与数据说明.md` §7）：

| 工具 | 归属能力 |
|---|---|
| `search_knowledge_base` | 知识检索（核心） |
| `lookup_employee` / `list_departments` / `query_budget` | 人事 / 组织查询 |
| `query_contract` | 合同查询（授权角色） |
| `redact_pii` / `risk_review_text` / `sanitize_for_storage` | 数据安全 / 脱敏 |

## 4. 主体资质核对

| 项目 | 状态 | 说明 |
|---|---|---|
| 开发者主体认证 | **待办** | 需企业开发者账号 / 营业执照（以平台要求为准） |
| 域名所有权 | **待办** | 公网域名 + **HTTPS 证书**（平台要求远程 MCP 必须 HTTPS） |
| 软件著作权 / 许可 | 就绪 | 本项目以 **Apache-2.0** 开源（见 `LICENSE`），含许可与免责声明 |
| 数据安全承诺 | 就绪 | 见 `docs/合规与数据说明.md`（本地推理、日志脱敏、fail-closed 鉴权） |
| 隐私政策 | **待办** | 需公网可访问页面，链接填入 `docs/合规与数据说明.md` §8 |
| OAuth 令牌策略 | 就绪 | MCP 原生 OAuth（`oauth_server.py`）：PKCE、access 1h / refresh ≥30d、授权码一次性；状态持久化 `data/oauth_state.json`（0600） |
| 服务可用性 | 待确认 | 平台建议 ≥99.9%，需运维侧给出保障方案 |
| 单次调用时限 | 就绪 | 服务端 `ToolTimeoutMiddleware` 30s 硬上限（`CONNECTOR_MAX_CALL_SECONDS`），并声明 `timeout: 30000` |

## 6. 阻塞项（提交前必须消除）

1. 公网 HTTPS 域名（替换 `mcp.json` 的 `url` 中 `YOUR_DOMAIN`）。
2. `SKILL.md` 的 `category`（当前 `04-DataAI`）与官方白名单核对。
3. OAuth 状态文件 `data/oauth_state.json` 的线上持久化 / 备份策略。
