# 合规与数据说明（企业知识助手 Connector）

> 本文用于 WorkBuddy 连接器上架审核，说明本应用处理哪些数据、数据在哪里、如何脱敏与审计。
> 文档中的 `<...>` 占位需在正式提交前替换为真实信息；标「待办」的条目在上架前必须落实。

## 1. 适用范围与部署形态

- 应用形态：**私有化 / 本地部署**。Web 前端、Agent、MCP Server 全部运行在客户自有主机上，不依赖我方云端。
- 连接器对外仅暴露**一个 MCP Server**（`mcp_servers/aggregate_server.py`，streamableHttp），由平台通过 HTTPS + OAuth 2.1（PKCE）调用；同一源另提供 `/healthz` 探针与 `/privacy` 隐私页。
- 服务端入口：`mcp_servers/connector.py`（`CONNECTOR_PUBLIC_URL` 启用 MCP 原生 OAuth；`CONNECTOR_TLS_CERT/KEY` 启用 HTTPS）。

## 2. 数据驻留（Data Residency）

| 数据 | 位置 | 是否出网 |
|---|---|---|
| 知识库 / 员工 / 客户 / 权限配置 | 部署主机本地 `data/*.json` | 否 |
| 大模型推理 | 默认本地 Ollama `http://127.0.0.1:11434/v1` | **否（默认）** |
| 审计日志 | 部署主机受管目录（`AUDIT_FILE`，默认 `/tmp/audit.jsonl`；生产 `/var/log/kbai/audit.jsonl`） | 否 |
| 反馈日志（用于改进） | 本地 `/tmp/guard_feedback.jsonl`、`/tmp/web_feedback.jsonl` | 否 |

- 模型端点 = `OLLAMA_BASE_URL`，默认 `127.0.0.1:11434`；模型 `MODEL_SMALL=qwen2.5:14b`、`MODEL_LARGE=qwen2.5:32b`（均本地）。
- **唯一可能出网的开关**：`LLM_FALLBACK_URLS`（默认空）。仅当运维显式配置该变量时，主模型失败才会回退到远程端点。
  - **上架前要求：确认 `LLM_FALLBACK_URLS` 未配置，或已就该远程端点签署数据处理协议（DPA）并在本文件补充说明。**
- 本应用不接入任何第三方统计 / 埋点 / 广告 SDK。

## 3. 数据分类与最小化

- **知识库**：29 篇制度/流程文档，按密级 `public` / `internal` / `confidential` 区分可见性（唯一声明点 `data/policy.json` 的 `docs_visibility`）。
- **员工目录**：姓名、部门、职位、职级、年假余额、入职日期。**不含手机号、身份证号等证件信息**。
- **客户信息**：企业名称、对接人称谓（如「王总」）、合同金额与账期。**不含个人手机号 / 身份证号**。
- **不采集 / 不落盘**：明文口令、令牌、证书；完整会话正文（审计仅保留 ≤200 字摘要）。

## 4. 个人信息（PII）处理与脱敏

单一实现：`mcp_servers/security_server.py` 的 `redact_pii`（MCP 工具，可被模型调用）。

| 类型 | 规则 | 示例 |
|---|---|---|
| 手机号 | 保留前 3 后 4 | `13812345678` → `138****5678` |
| 身份证 | 保留 6 + 4 | `110101199001011234` → `110101********1234` |
| 银行卡 | 保留前 4 后 4 | `6222021234567890123` → `6222***********0123` |
| 邮箱 | 仅留首字符 | `zhangsan@corp.com` → `z***@corp.com` |
| 地址 | 保留行政区，掩码门牌 | `北京市朝阳区建国路88号` → `北京市朝阳区******` |
| 内部人名 | 保留姓 | `张伟` → `张*` |

- **出口防线**：`agent/injection.py::mask_pii` 对最终回答再脱敏手机号 / 身份证。
- **存储前清洗**：`sanitize_for_storage` = 脱敏 PII + 敏感词风险检查。
- 敏感词表与内部人名表均由 `data/config.json` 配置，可随客户制度调整。

## 5. 日志与审计

- **审计日志**：路径由 `AUDIT_FILE` 指定，默认 `/tmp/audit.jsonl`；**生产必须指向受管目录**（如 `/var/log/kbai/audit.jsonl`，`start_connector.sh` 已默认之）。每条工具调用记录：
  `{ts, time, user, department, role, tool, args, sensitive, shared, result}`。
- **日志脱敏（已实现）**：`args` 与 `result` 写入前统一经 `security_server.redact_pii` 处理，再做长度截断（args 每值 ≤80 字，result ≤200 字）。
  这样即使用户把**待脱敏的 PII 作为参数传入**，也不会以明文落入日志。
- **权限（已实现）**：文件新建即 `0600`，每次写入后校正，仅服务账号可读写。
- **保留期（已实现）**：单文件超过 `AUDIT_MAX_BYTES`（默认 5 MiB）即轮转为 `.1`，仅保留 `AUDIT_BACKUPS`（默认 3）份，最旧自动删除；保留期 = 份数 × 单文件上限（默认约 20 MiB 封顶）。
- **不包含**：完整回答正文、明文口令 / 令牌（认证走 PBKDF2 派生，口令本身不落盘）。
- 审计写入失败时**静默降级**，不影响主流程（可用性优先）。
- 反馈日志 `/tmp/guard_feedback.jsonl`、`/tmp/web_feedback.jsonl` 仅用于安全拦截统计与效果改进，不含凭证。
- 回归：`tests/test_audit.py`（权限 / 脱敏 / 轮转 / 保留 12 条）。

## 6. 账号、访问控制与凭证

- **认证 fail-closed**：`agent/secure_auth.py`（PBKDF2-HMAC-SHA256）。账号表 `data/auth_users.json` **无通配账号、无隐式默认口令**，未登记账号一律拒绝。
  - 具名账号示例：陈志强 / 张伟 / 刘洋；生产口令经 `tools/set_password.py` 设置或用 `AUTH_USERS` 环境变量注入。
- **RBAC**：`data/policy.json` 为唯一权限声明点（客户可见角色、文档可见性、人工台角色）。
- **连接器鉴权**：**MCP 原生 OAuth 2.1（公共客户端 + PKCE，`auth_mode` 省略）**，由 `mcp_servers/oauth_server.py` 提供元数据发现 / 动态注册 / `/oauth/authorize` / `/oauth/token`；access_token ≈1h、refresh_token ≥30d，授权码一次性 ≈10min。客户端与令牌状态落盘 `data/oauth_state.json`（`0600`，已 gitignore），不在任何文件硬编码凭证。
- **无用户会话下的对外收口**：`connector/mcp.json` 的 `disabledTools` 隐藏 4 个工具（见 §7），因为它们的权限判定依赖**模型传入的 `user_role` 参数**，在无用户会话时不可信。这符合平台「不得依赖模型传入用户身份」的要求。
- **凭证管理**：全部经环境变量注入，不写入仓库 / 数据库；`.gitignore` 覆盖 `data/auth_users.json`、`data/secret.key`、`.env`、`*.pem`、`*.key`；`data/secret.key` 文件权限 `0600`。

## 7. 对外暴露的工具（仅只读）

聚合端点共 12 个工具，连接器对外**开放 8 个只读 / 计算类**，**禁用 4 个**：

| 开放（8） | 说明 |
|---|---|
| `search_knowledge_base` | 检索知识库（按密级返回） |
| `lookup_employee` | 查询员工（脱敏后返回） |
| `query_budget` | 查询部门预算 |
| `list_departments` | 列出部门 |
| `query_contract` | 查询合同（授权角色） |
| `redact_pii` | PII 脱敏 |
| `risk_review_text` | 敏感词风险检查 |
| `sanitize_for_storage` | 存储前清洗 |

| 禁用（4） | 原因 |
|---|---|
| `create_leave_request` / `create_ticket` | 写操作尚未持久化，且平台侧不应由模型直接提交 |
| `get_customer_info` / `list_customers` | 权限判定依赖模型传入的 `user_role`，Token 模式不可信 |

## 8. 隐私政策与用户告知

- 隐私政策公开链接：`https://<YOUR_DOMAIN>/privacy`。**该页面由连接器自身在同一 HTTPS 源上提供**（`mcp_servers/public_app.py`），无需另建静态站点。
- 内容来源：内置模板（与本节要点一致），可用 `CONNECTOR_PRIVACY_FILE` 指向法务终稿 HTML 覆盖；运营主体与联系邮箱由 `CONNECTOR_OPERATOR` / `CONNECTOR_PRIVACY_CONTACT` 注入（**默认占位必须在上线前替换**）。
- 可用性探针：`https://<YOUR_DOMAIN>/healthz` 返回服务状态（不含任何凭证），供平台/自建拨测使用。
- 告知要点：本应用处理企业知识库、员工目录、客户与合同信息，用于企业内部问答；数据默认不出本机；用户可联系隐私事务邮箱行使查询、更正、删除权。
- 建议在 Web 登录页与隐私政策页同步展示上述要点。

## 9. 上架前合规检查清单

- [ ] 公网 HTTPS 端点已部署（`connector/mcp.json` 的 `url` 已替换域名），OAuth 端点与回调可达
- [ ] 隐私政策页面已上线且可访问（`/privacy`；已用终稿覆盖默认模板并替换运营主体/邮箱）
- [ ] 确认未配置 `LLM_FALLBACK_URLS`（或已补充 DPA 说明）
- [ ] 审计日志受管目录已就绪（`AUDIT_FILE` 指向持久盘，`0600` + 轮转/保留已生效）
- [ ] `AUTH_USERS` 以环境变量注入，仓库内无任何真实口令
- [ ] 证书 / 私钥不随代码分发
