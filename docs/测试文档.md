# 测试文档

本助手测试分五层：**工具单测 / 逻辑回归基线 / 路由+工具集成 / 工作流单元 / 端到端（HTTP）**，外加**飞轮评测集**做能力轮回验证。

统一前置：
- MCP 启动（用于集成层与端到端）：`./start_all.sh`
- LLM 在线：`.venv/bin/python tools/llm_health.py`
- 涉及 `agent/*` 的脚本一律用 `.venv/bin/python`（依赖 fastmcp）

## 0. 线上质量监控（monitor）

`tools/monitor.py` 聚合 web/guard 反馈与人工兜底队列，输出三层指标：

```bash
.venv/bin/python tools/monitor.py            # 全部历史
.venv/bin/python tools/monitor.py --since 24 # 最近 24h
```

输出：
- **[1] 端到端质量**：会话量、PASS率、500率、降级率、低置信率、均耗时、workflow 分布、活跃用户
- **[2] 人工兜底**：needs_human 产生量 / 已回填 / 待办（未完成任务的"人形成功线"）
- **[3] 轨迹质量**（需会话带 trace，`agent/web_app.py` 自本轮起落盘）：平均步数、平均不同工具数、重复调用步率、白名单外调用率、工具报错率、Top 工具

> trace 是每次工具调用 `{tool, args摘要, obs前200字符}` 摘要。判断口径：重复调用=相邻同工具；白名单外=`obs` 含"白名单…拒绝/未知工具"；工具报错=`obs` 含 `"error"`。这些即"工具可靠性 + 轨迹合理性"层面的体检。
> 验收：低置信率从基线（首次跑出的真实数字）随时间/飞轮回灌应下降；白名单外调用率应≈0（防幻觉写操作）。

## 3. 工作流单元（workflow.py，无需 LLM）

覆盖 detect / 缺失字段判定 / 草稿生成 / 审批查询分类：

```bash
.venv/bin/python - <<'EOF'
import sys; sys.path.insert(0, 'agent')
from workflow import detect_workflow, missing_fields, build_draft, kind_of
# 9 类命中
assert detect_workflow("我要报销 700 元 4月5日 出差住宿") == "报销申请"
assert detect_workflow("帮刘洋申请4月15-16日休年假两天") == "请假申请"
assert detect_workflow("申请开通数据库读权限") == "权限申请"
assert detect_workflow("我的报销审批到哪了？") == "审批查询"
assert detect_workflow("技术部预算剩多少？") is None          # 非流程题不误命中
assert detect_workflow("新员工培训要几天？") is None          # 查询制度≠培训申请
# 缺字段引导
assert missing_fields("我要报销", "报销申请") == ["事由", "费用发生日期", "金额(元)"]
# 字段齐 → 草稿含关键值
d = build_draft("帮刘洋申请4月15-16日休年假两天", "请假申请", {"name":"刘洋","department":"技术部"})
assert "4月15日" in d and "4月16日" in d and "年假" in d
print("workflow OK")
EOF
```

## 4. 端到端（HTTP，需 LLM + MCP + web_app）

```bash
.venv/bin/python agent/web_app.py 8788 &
# A. 未登录
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8788/          # 302 → /login
curl -s -X POST http://127.0.0.1:8788/api/chat -H 'Content-Type: application/json' -d '{"question":"hello"}'  # 401

# B. 登录两个角色
curl -s -c /tmp/ck_m -X POST http://127.0.0.1:8788/api/login -H 'Content-Type: application/json' \
     -d '{"name":"刘洋","password":"123456"}'      # 经理 manager
curl -s -c /tmp/ck_e -X POST http://127.0.0.1:8788/api/login -H 'Content-Type: application/json' \
     -d '{"name":"黄国栋","password":"123456"}'    # 普通员工

# C. RBAC：员工查客户被拒，经理可见
curl -s -b /tmp/ck_e -X POST http://127.0.0.1:8788/api/chat -H 'Content-Type: application/json' \
     -d '{"question":"查一下华宇科技的客户信息"}'   # 期望：员工侧 run_tool 返回 denied / 无权访问
# 经理侧应返回真实客户数据

# D. 工作流三态（经理会话）
curl -s -b /tmp/ck_m -X POST http://127.0.0.1:8788/api/chat -H 'Content-Type: application/json' \
     -d '{"question":"我要报销"}'                   # model=web/workflow-guide, needs_fields 非空
curl -s -b /tmp/ck_m -X POST http://127.0.0.1:8788/api/chat -H 'Content-Type: application/json' \
     -d '{"question":"帮刘洋申请4月15-16日休年假两天"}'  # model=web/workflow-draft, 含起始/结束日期
curl -s -b /tmp/ck_m -X POST http://127.0.0.1:8788/api/chat -H 'Content-Type: application/json' \
     -d '{"question":"我的报销审批到哪了？"}'          # model=web/workflow-inquiry，引导到 OA
curl -s -b /tmp/ck_m -X POST http://127.0.0.1:8788/api/chat -H 'Content-Type: application/json' \
     -d '{"question":"拿华宇科技的合同号查询合同"}'      # 走真实 query_contract

# E. 人工兜底坐席链路
curl -s -b /tmp/ck_m http://127.0.0.1:8788/api/human/list      # 待办队列（应能看到不能答的问题）
curl -s -b /tmp/ck_m -X POST http://127.0.0.1:8788/api/human/answer -H 'Content-Type: application/json' \
     -d '{"qhash":"{\"q\":\"<问题>\"}","answer":"<人工答案>"}'  # 回填 → 同步写入 flywheel(human)
```

验收标准：A 两步、C RBAC 边界、D 三态 model 标识与内容、E 队列出现/回填后队列消失且 `web_feedback` 产生 human 记录。

## 5. 飞轮评测集（能力轮回验证）

```bash
# 采集/分类 → 候选清单
.venv/bin/python tools/flywheel.py report
# 人工在 tools/flywheel/candidates.md 补 expected 列 + 决策理由(reason) 列后回灌评测集
.venv/bin/python tools/flywheel.py promote
# 跑评测集（judge 判分：数字断言→关键句→全文包含；加 --judge llm 增加语义复核层）
.venv/bin/python tools/flywheel.py bench
.venv/bin/python tools/flywheel.py bench --judge llm
```

### 判分层级（确定性优先，LLM 复核兜底）

1. **确定性 judge**（默认 `bench`，判分可解释、零成本）：数字断言 → 关键句命中 → 全文包含。
2. **LLM-as-a-Judge**（`bench --judge llm`）：确定性判 FAIL 后，用本地 qwen2.5:14b 复核"回答与标准答案是否语义一致"（允许换措辞；要点缺失/意思相反=不一致）。意图：**防"答对但被判错"**——模型换说法时先字面判不过、再语义判。
3. **人工评审**：`candidates.md` 末列 **决策理由(reason)** 记录"这个答案凭什么定"（制度X条/人工约定/待查证）。歧义样本必须写明；入库时 reason 随评测题一并写入 `benchmark.jsonl` 与 `promote_docs.md`。意图：**防"没把握的答案被当标准答案固化"**。

> 验证过的行为：同义变体会被 LLM 判对（确定性误杀 4→纠正）；"只答一部分、漏掉其他档位"且答错内容时为 FAIL；`--judge llm` 在 14b 不可用时自动降级保留确定性结论，不阻塞。

## 7. 版本与提交流程

- 开发在本地 commit（`feat/fix/chore/test + 简述`），**多轮验证通过再 push**；当前项目直接 on `main` 快进。
- 生成物（`candidates.md`、`benchmark.jsonl`、`promote_docs.md`）随闭环提交；运行时数据（`feed.db`、`/tmp/*.jsonl`）不入库（`feed.db` 已 .gitignore）。

## 8. 已知缺口（当前基准）

- `tests/run_suite.py` 基准 **45/45**：路由（含写操作 `blocked_write` 拒绝语义）+ 实际工具调用全过。
- 自建前端链路（`web_app.py` / `react_agent.py`）现支持**多轮对话历史**：前端攒 `turns`（最近 20 轮）→ `/api/chat` 收 `history` → `agent(history=...)` 拼进 messages（最近 8 轮 + 单条 600/1200 截断）。验证过"孙敏在哪个部门 → 这个部门有多少人"：带历史答"财务部 16 人"，同问不带历史会落默认部门（错）。
- 多轮边界：历史只进普通问答链路（`agent()`）；`workflow-guide/draft` 代码分支暂不消费历史，补字段那类续问仍建议一问题全字段。
