# 部署与上线（连接器）

面向「把连接器发布到 WorkBuddy 开放平台」的部署手册。目标形态：

```
WorkBuddy 客户端 ──HTTPS──► 反向代理(Caddy/Nginx, 终止 TLS) ──HTTP──► 聚合连接器 :8000
                                                                       ├─ MCP /mcp (streamableHttp, OAuth 2.1 PKCE)
                                                                       ├─ /healthz  可用性探针
                                                                       └─ /privacy  隐私政策页
                          内部 8001 docs / 8002 ops / 8003 security / 8004 memory（仅内网/localhost）
```

连接器**只监听一个对外端点**（`aggregate_server.py`，端口 8000），四个子服务只在 `127.0.0.1` 供其挂载调用。

## 1. 前置条件

- Linux 服务器（2 vCPU / 4 GB 起），Python 3.11+，模型与数据均在本机（数据驻留，默认不出网）。
- 已备案/可用的 **公网域名**，且能为其签发 TLS 证书（平台要求端点 HTTPS）。
- Ollama 本地模型可用（`bge-m3` 用于向量检索，可选）。
- 平台要求：可用性 ≥99.9%，单次请求 <30s。

## 2. 环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `CONNECTOR_PUBLIC_URL` | ✅ | 对外 HTTPS 根地址，如 `https://kb.example.com`。设置即启用 MCP 原生 OAuth |
| `CONNECTOR_HOST` / `CONNECTOR_PORT` | | 监听地址/端口，默认 `0.0.0.0` / `8000` |
| `CONNECTOR_OAUTH_STATE` | ✅ | OAuth 状态文件路径，默认 `data/oauth_state.json`（权限自动 0600） |
| `CONNECTOR_TLS_CERT` / `CONNECTOR_TLS_KEY` | | 应用层 HTTPS；由反代终止 TLS 时留空 |
| `CONNECTOR_MAX_CALL_SECONDS` | | 工具硬超时，默认 `30`（协议层兜底，超时返回可读 `ToolError`） |
| `CONNECTOR_PRIVACY_FILE` | | 自有隐私政策 HTML 路径（法务终稿），覆盖内置模板 |
| `CONNECTOR_OPERATOR` / `CONNECTOR_PRIVACY_CONTACT` | ✅ | 隐私页显示的运营主体 / 联系邮箱，上线必须替换默认占位 |
| `AUDIT_FILE` | ✅ | 审计日志路径，指向**受管目录**（如 `/var/log/kbai/audit.jsonl`） |
| `AUDIT_MAX_BYTES` / `AUDIT_BACKUPS` | | 审计单文件上限（默认 5 MiB）与保留份数（默认 3） |
| `AUTH_USERS` | | 自研侧账号表（连接器走 OAuth，不依赖此项） |
| `OLLAMA_BASE_URL` | | 本地模型地址，默认 `http://127.0.0.1:11434/v1` |
| `LLM_FALLBACK_URLS` | | **唯一出网开关**，默认空 = 完全本地、不向外部发送数据 |

## 3. TLS 终止（反向代理）

### Caddy（最简，自动签发证书）

```caddyfile
kb.example.com {
    # SSE / streamableHttp 不可缓冲、不可压缩改写
    reverse_proxy 127.0.0.1:8000 {
        flush_interval -1
        transport http {
            read_timeout 35s
            write_timeout 35s
        }
    }
    header {
        Strict-Transport-Security "max-age=31536000; includeSubDomains"
        X-Content-Type-Options nosniff
    }
}
```

### Nginx（等价）

```nginx
server {
    listen 443 ssl http2;
    server_name kb.example.com;
    ssl_certificate     /etc/letsencrypt/live/kb.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/kb.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;            # 关键：关闭缓冲以支持流式响应
        proxy_read_timeout 35s;
        proxy_send_timeout 35s;
        chunked_transfer_encoding on;
    }
}
```

要点：
- `proxy_buffering off` / `flush_interval -1` —— 否则流式响应被攒住，客户端等超时。
- 超时略大于应用层 30s（如 35s），让应用自己先超时并返回可读错误。
- 反代必须放行 `/.well-known/*` 与 `/oauth/*`（默认全量放行即可，勿单独拦截）。

## 4. 启动与常驻

```bash
# 首次准备
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
ollama pull bge-m3            # 可选：向量检索
sudo mkdir -p /var/log/kbai && sudo chown "$USER" /var/log/kbai

# 前台试跑
CONNECTOR_PUBLIC_URL=https://kb.example.com \
AUDIT_FILE=/var/log/kbai/audit.jsonl \
CONNECTOR_PRIVACY_CONTACT=privacy@example.com \
CONNECTOR_OPERATOR='XX 科技有限公司' \
./start_connector.sh
```

`/etc/systemd/system/kbai-connector.service`（仓库 `deploy/kbai-connector.service` 现成可直接用）：

```ini
[Unit]
Description=Enterprise Knowledge Assistant Connector
After=network-online.target ollama.service
Wants=network-online.target

[Service]
User=kbai
WorkingDirectory=/opt/kbai/enterprise-ai-assistant
EnvironmentFile=/etc/kbai/connector.env
ExecStart=/opt/kbai/enterprise-ai-assistant/start_connector.sh
Restart=always
RestartSec=3
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/var/log/kbai /opt/kbai/enterprise-ai-assistant/data

[Install]
WantedBy=multi-user.target
```

一步安装：`sudo install -m 600 deploy/connector.env.example /etc/kbai/connector.env`，
编辑后 `sudo install -m 644 deploy/kbai-connector.service /etc/systemd/system/ &&
sudo systemctl daemon-reload && sudo systemctl enable --now kbai-connector`。

- 环境变量（含 `CONNECTOR_PUBLIC_URL`、`AUDIT_FILE`、隐私页占位替换）放 `/etc/kbai/connector.env`，`chmod 600`，**不入库**。
- **无 systemd 的主机**：可用 `deploy/watchdog.sh` 兜底（轮询 `/healthz`，连挂自动拉起），
  但生产推荐 systemd。

## 5. OAuth 状态持久化与多实例

- 状态（注册的客户端、授权码、访问/刷新令牌）落在 `CONNECTOR_OAUTH_STATE`，**原子写 + 0600**。
- 单实例：指向持久化磁盘（非 `/tmp`），随服务一起备份；否则重启后客户端须重新授权。
- **多实例/滚动发布：必须让所有实例共享同一状态文件**（NFS/云盘），否则在 A 实例授权、请求落到 B 实例会被判未授权。共享存储不可用时，改用 `CONNECTOR_OAUTH_STATE` 指向的外部存储方案前，请先评估——当前的实现是单文件后端，不支持无共享存储的水平扩展。
- 备份：纳入日常备份（含文件权限）；恢复后令牌仍然有效。
  全量备份用仓库自带 `./tools/backup.sh`（一致性快照 + 保留轮转），恢复步骤见 `docs/备份与恢复.md`。

## 6. 业务数据接入（替换合成数据）

上线第一天把合成演示数据换成客户真实数据：参考 `samples/data_templates/` 整理 CSV，
用 `tools/import_customer_data.py --wipe` 导入（业务表落 SQLite、制度文档并入
`documents.json`），全程本地、不出网。详细步骤见 `docs/数据接入.md`；导入前先
`./tools/backup.sh` 打基线。

## 7. 监控与可用性（≥99.9%）

- 健康探针：`GET https://kb.example.com/healthz` → `200 {"status":"ok","auth":"oauth(pkce)",...,"uptime_s":...}`。
- 建议：外部拨测 1 分钟/次 + 进程级 `Restart=always`，并对以下指标告警：
  - `/healthz` 非 200 或超时；
  - 审计日志中 `ToolError ... 超过 30s` 出现频率；
  - 磁盘（审计/状态/索引）水位。
- 上游模型（Ollama）建议由 systemd 托管并在探针里一并检查，避免「连接器活着但检索不可用」。

## 8. 审计与隐私合规收口

- 审计日志：`AUDIT_FILE` 指向受管目录，**新建即 0600**，超过 `AUDIT_MAX_BYTES` 轮转为 `.1/.2/...`，仅保留 `AUDIT_BACKUPS` 份（保留期 = 份数 × 单文件上限）。参数与结果在落盘前已 PII 脱敏。
- 隐私政策：`https://<域名>/privacy` 即为公网页面。上线前用 `CONNECTOR_PRIVACY_FILE` 指向法务终稿，并替换 `CONNECTOR_OPERATOR` / `CONNECTOR_PRIVACY_CONTACT`；把该 URL 填入 `docs/合规与数据说明.md` 的隐私政策占位处与平台表单。
- 数据驻留：保持 `LLM_FALLBACK_URLS` 为空（默认即空），所有推理与检索在本机完成。

## 9. 延迟与 30s 硬上限

- 连接器暴露的检索/查询工具本身不走大模型，正常远低于 30s；协议层另设 `CONNECTOR_MAX_CALL_SECONDS=30` 兜底，超时返回可读错误而非挂起。
- 实测（本机，8 个只读工具经 OAuth 连接器逐个调用）：最慢为 `search_knowledge_base` ≈1.2s（含向量召回），其余均 <0.01s，全部通过。
- 自研问答界面（非连接器）的**大模型链路**实测 p90≈23s、max≈45s：如对外暴露对话式能力，请把 `LLM_TIMEOUT` 压到 30s 内、减少重试，或将模型切换到更低延迟的本地模型。
- 如检索因首次加载模型偏慢，预热一次（`curl /healthz` 后调用一次 `search_knowledge_base`）再接入平台。

## 10. 真机验收清单（部署后逐项打勾）

1. `curl -s https://<域名>/healthz` = 200，`auth` 为 `oauth(pkce)`。
2. `curl -sI https://<域名>/privacy` = 200（并确认是法务终稿）。
3. `curl -s https://<域名>/.well-known/oauth-protected-resource` = 200 且 `resource` 以 `/mcp` 结尾。
4. `curl -s https://<域名>/.well-known/oauth-authorization-server` = 200，含 `/oauth/token`、`S256`、`"none"`。
5. 无令牌 `POST /mcp` = 401，且响应头含 `WWW-Authenticate: Bearer resource_metadata="..."`。
6. WorkBuddy 客户端内实际添加连接器 → 浏览器完成授权 → 工具列表出现 8 个只读工具 → 调 `search_knowledge_base` 有结果。
7. `workbuddy://` 私有回调可用；若客户端回退到 `http://127.0.0.1:<动态端口>/oauth/callback` 亦能完成。
8. 授权过期后能自动续期（refresh）且不需要用户重新走浏览器。
9. 反向代理未缓冲流式响应（长回答能持续输出，不一次性吐出）。
10. 服务重启后**已授权客户端仍可用**（`CONNECTOR_OAUTH_STATE` 持久化生效）。

## 11. 上架提交与回滚

```bash
cd connector && zip -r ../enterprise-knowledge-assistant.zip . -x '.*'
```

- 提交前按 `connector/README.md`「提交前检查」逐项核对（`category` 与运营确认、`YOUR_DOMAIN` 替换为真实域名）。
- **回滚**：保留上一版本的连接器包与 `CONNECTOR_OAUTH_STATE` 备份；回滚时恢复二进制/配置并**一并恢复状态文件**，避免令牌失效导致用户被强制重新授权。
