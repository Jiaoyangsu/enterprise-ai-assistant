# 真实数据接入（上线第一天替换合成数据）

当前库默认是合成演示数据（`data_generated.py` 播种到 `data/app.db` + `data/documents.json`）。
上线时用导入适配器换成客户真实数据——**改配置、不改代码**。

## 1. 准备 CSV

按 `samples/data_templates/` 的表头整理（UTF-8，列名固定；多余列忽略；数值非法行自动跳过）：

| 文件 | 主键 | 字段 |
|---|---|---|
| `employees.csv` | name | name,department,position,level,leave_balance,hire_date |
| `departments.csv` | name | name,code,bg,manager,headcount |
| `budgets.csv` | department | department,annual,spent,remaining,bg |
| `customers.csv` | name | name,industry,contact,level,contract_amount,credit |
| `contracts.csv` | contract_id | contract_id,customer,status,amount,sign_date,owner |
| `documents.csv` | id | id?,title,content,keywords?,classification?,department?,version? |

- `documents.csv` 的 `id` 可省（自动分配 `DOC-xxx`）；给出则按 id **覆盖**已有文档。
- `keywords` 分号/逗号分隔；`content` 为制度正文，可含换行（用引号包裹）。

## 2. 演练（dry-run）

```bash
cp -r samples/data_templates ./import        # 得到空模板表
# 在 ./import/ 里填真实数据；注意 employees 等留注释行或空行不影响
.venv/bin/python tools/import_customer_data.py \
    --data-dir ./import --db /tmp/import_dry/app.db --dry-run
```

只计算不写盘；确认每表行数符合预期再正式导入。

## 3. 正式导入

```bash
# --wipe：先清空合成数据再导入（避免残留）——正式换数据必须带
.venv/bin/python tools/import_customer_data.py \
    --data-dir ./import --db data/app.db --wipe

# 验证
sqlite3 data/app.db "SELECT COUNT(*) FROM employees; SELECT COUNT(*) FROM customers;"
```

也可以只导某几张表（如只导 `documents.csv` 不导业务表），不给文件的表保持原样。

## 4. 生效与回归

- docs_server 按 mtime 热重载 `documents.json`，**业务表需重启 8001–8004**（或等下次启动）：
  `./start_all.sh`。
- 建议先跑 `./check_servers.sh` + 一条 QA 问题（如"技术中心多少人"、"差旅报销额度"），
  确认读的是新数据。
- `documents.json` 的 `version` 字段保留原值。

## 注意事项

- 导入**不出网、不落凭证**；CSV 本身含员工/客户敏感信息，接入后请按密级处置原始文件。
- 与「审计/日志」不冲突：读数仍走统一 store，工具调用照常审计。
- 真实数据量若很大（>10 万条员工），先做批量性能验证；向量化超大知识库需分批并预留
  `data/embeddings_cache.json` 空间。
- 上线前：`./tools/backup.sh` 打一次基线备份，导入后如异常用 `docs/备份与恢复.md` 恢复。
