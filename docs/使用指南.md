# 使用指南

面向两类读者：**员工用户**（用它办事、问制度）和**运维/管理员**（部署、配置、回填人工）。

---

## 1. 面向员工用户

### 1.1 登录

- 浏览器打开 `http://<服务器>:8788`，自动跳转 `http://127.0.0.1:8788/login`。
- 输入**姓名 + 密码**（默认 `123456`，管理员可改 `auth_users.json`）。
- 登录后顶栏显示当前登录人，可点击「退出」注销。
- 未登录访问首页/坐席/聊天接口都会被 302 到登录页，`/api/chat` 未登录返回 401。

> 密码表格式见 `auth_users.json`：`{"姓名": "密码", "*": "默认密码"}`。`*` 表示"没单独配置的姓名用默认密码"。

### 1.2 能问什么（能力边界）

| 类别 | 示例 | 说明 |
|------|------|------|
| 员工/考勤 | 我年假还剩几天 | 工具返回真实数据 |
| 预算 | 技术部预算剩多少 | 按部门/事业群查询 |
| 客户/合同 | 华宇科技信用怎么样 / 审批中的合同 | **经理角色可见**，普通员工被拒 |
| 制度/流程 | 报销最多能报多少 / 新员工培训几天 | 检索 27 篇知识库文档 |
| 合规 | 把这段手机号脱敏、检查敏感词 | security 工具 |
| 流程申请 | 我要报销 / 请两天年假 | 见 1.3 |

拒绝场景（尊重边界）：与工作无关、他人隐私、未登录角色访问客户信息、任何写操作（提交/创建/开单）一律不执行，只引导到 OA 办理。

### 1.3 流程申请怎么用（workflow）

目前申请类事务走**引导 → 草稿**流程，系统绝不代提交：

1. **缺字段** → 助手列出缺失项让你补齐（如：我要报销 → 缺 事由/费用发生日期/金额）。
2. **字段齐** → 直接给出可提交的**草稿清单**（含申请人、日期、金额、制度核对要点），末尾提示到 OA「我的申请」正式提交。
3. **审批进度查询** → 告知"OA 暂无在线数据，请到 OA「我的申请」查看"，不编造审批节点；合同审批走 `query_contract` 返回真实状态。

支持 9 类：报销申请、请假申请、加班申请、资产申领、出差申请、权限申请、证明开具、培训申请、审批查询。

### 1.4 电话/文本渠道（dsh Web 8787）

企业聊天界面由 dsh 框架提供（`--profile web`，端口 8787），能力同自建前端（复用同一 ReAct Agent）。无登录态时默认身份=刘洋 / 技术部 / 已登录 manager。

## 2. 面向运维/管理员

### 2.1 启动与健康检查

```bash
./start_all.sh                       # 3 个 MCP Server (8001/8002/8003)
.venv/bin/python agent/web_app.py 8788   # 自建前端（登录/坐席）
.venv/bin/python tools/llm_health.py     # LLM 探活，异常会自动告警
./check_servers.sh                       # MCP 连通性快检
```

dsh 框架：`export PATH="/opt/homebrew/bin:$PATH"; export OLLAMA_PLACEHOLDER_KEY=ollama; dsh --profile web --no-open --port 8787`

### 2.2 LLM 后端切换

```bash
./tools/switch_backend.sh local   # 本地 ollama (qwen2.5:14b, 127.0.0.1:11434)
./tools/switch_backend.sh autodl  # AutoDL 32b (备用, 需隧道)
```

### 2.3 人工兜底坐席（关键运营位）

当助手"低置信/无法确认/500"时，答案会写入队列：

- 队列文件：`/tmp/human_queue.jsonl`
- 坐席页：登录后访问 `http://127.0.0.1:8788/human`（或 API `/api/human/list`）
- 操作：查看待办 → 填人工答案 → 提交（`/api/human/answer`）→ 自动回灌到飞轮（category=human）并给引擎学习/评测。

### 2.4 数据飞轮操作

```bash
.venv/bin/python tools/flywheel.py report     # 采集样本 → 分类 → 生成 candidates.md（人工标注 expected + 决策理由列）
.venv/bin/python tools/flywheel.py promote    # 已标 expected 的候选 → 录入评测集 + 写 benchmark.jsonl/promote_docs.md
.venv/bin/python tools/flywheel.py bench      # 跑评测集，输出接答准确率
.venv/bin/python tools/flywheel.py bench --judge llm   # 确定性判 FAIL 后加一层 LLM 语义复核（防"答对但被判错"）
.venv/bin/python tools/monitor.py             # 线上质量监控（PASS/500/低置信/待办/轨迹质量），可加 --since 24 看最近 24h
```

- `candidates.md`：人工在 expected 列补标准答案，并在**决策理由(reason)**列记"凭什么定"（制度条款/人工约定/待查证）；human 类别自动预填（=人工答案），unanswered 留空等真实制度材料。
- `benchmark.jsonl`：评测集（question/expected/source/category/reason）；bench FAIL 代表知识缺口，需补文档或人工答案。
- `bench --judge llm`：判分层级 = 确定性(数字/句子/包含) 优先，FAIL 后 14b 语义复核；模型不可用时自动降级不阻塞。
- `monitor.py` 三层：1) 端到端质量（PASS/500/降级/低置信率/耗时）；2) 人工兜底待办量；3) 轨迹质量（步数/重复调用/白名单外调用率/工具报错率）。低置信率是飞轮效果的核心指标。

### 2.5 常见维护

| 事项 | 做法 |
|------|------|
| 换登录密码 | 改 `auth_users.json`，无需重启 |
| 员工目录变更 | 改 `mcp_servers/data.py` 或跑 `tools/generate_data.py` |
| 知识库补文档 | `mcp_servers/documents_extra.py` 内加文档（需 id/keywords/密级元数据） |
| guard 规则改动 | 改 guard 源码后三分同步（含 dsh 的 node_modules 副本），并重启 dsh |
| 清 session | 重启 web_app（session 存内存） |
