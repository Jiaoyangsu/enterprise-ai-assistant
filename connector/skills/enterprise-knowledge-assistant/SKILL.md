# 企业知识助手 · 使用说明

本连接器把企业知识库与业务数据以只读方式提供给 AI。**所有写入类工具与依赖用户角色的客户信息工具已在服务端隐藏**，AI 只会看到下列 8 个只读工具。

## 可用工具

| 工具 | 用途 | 关键参数 |
| --- | --- | --- |
| `search_knowledge_base` | 检索规章制度/知识库（含密级与部门权限过滤） | `query`(必填) |
| `lookup_employee` | 查询员工部门/职位/职级/年假余额/入职日期 | `name`(必填) |
| `query_budget` | 查询部门或事业群的年度预算、已用、剩余（万元） | `department` |
| `list_departments` | 列出事业群/部门、负责人、人数 | 无 |
| `query_contract` | 查询合同状态（审批进度/金额/负责人） | `status` 等 |
| `redact_pii` | 对文本中的手机号/身份证/邮箱/银行卡/地址/人名脱敏 | `text`(必填) |
| `risk_review_text` | 检查文本是否含高危敏感词 | `text`(必填) |
| `sanitize_for_storage` | 入库前清洗：先脱敏 PII，再查敏感词 | `text`(必填) |

## 调用规则

1. **先检索后回答**：涉及制度、流程、金额、人员的问题，必须先调用对应工具取数，不得凭记忆作答；工具返回“未找到”时如实告知，不要编造。
2. **姓名要精确**：`lookup_employee` 需传完整姓名（如“韩梅梅”）；用户只给姓氏或歧义称谓时，先向用户确认。
3. **脱敏优先**：任何要把原文外发、写入或展示给第三方的场景，先调用 `redact_pii` / `sanitize_for_storage`。
4. **只读边界**：本连接器不提供提交请假、创建工单、查询客户明细的能力。用户要求这类操作时，明确说明当前连接器仅供查询，并引导其通过企业内部系统办理。
5. **权限提示**：`search_knowledge_base` 可能返回“需登录后方可查看”或“无权访问”，这是密级/部门权限过滤的结果，应向用户如实转达，不要绕行。

## 认证与错误恢复

- 本连接器采用 **MCP 原生 OAuth（公共客户端 + PKCE）**：首次连接会自动打开浏览器完成授权，用户无需手动填写令牌。
- 若调用返回 `401`：多为授权过期。access_token 约 1 小时、refresh_token 不少于 30 天，客户端会自动续期并重试；仍失败时提示用户在连接器设置中重新授权。
- 单次调用应在 30 秒内返回；超时（服务端 30s 硬上限）或返回 `5xx` 时，说明服务端临时不可用或查询范围过大，建议缩小范围后重试，不要重复发起相同调用（本连接器无写操作）。
- 参数错误会返回可读的失败信息（如“未找到员工：XXX”），据此修正参数后重试，不要臆造参数值。

## 输出要求

- 金额统一标注单位（万元），日期使用 `YYYY-MM-DD`。
- 引用制度条款时给出文档标题/编号作为出处。
- 不输出任何完整个人敏感信息（若用户提供原文，先脱敏再复述）。
